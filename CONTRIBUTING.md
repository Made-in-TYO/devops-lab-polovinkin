\# Правила участия в проекте



Репозиторий учебный, но правила ниже повторяют те, по которым работают

реальные команды: любое изменение попадает в основную ветку только через

Pull Request.



\## Ветки



\- `main` — стабильная ветка, прямые коммиты в неё не делаются.

\- `develop` — ветка разработки, из неё открывается Pull Request в `main`.

\- Ветки под отдельные задачи именуются по смыслу:

&#x20; `feature/краткое-описание` для новой функциональности,

&#x20; `fix/краткое-описание` для исправлений.



\## Коммиты



\- Сообщение пишется в повелительном наклонении на английском языке:

&#x20; `Add contributing guidelines`, а не `Added` и не `Добавил`.

\- Первая строка — не длиннее 72 символов, без точки в конце.

\- Один коммит — одно логически завершённое изменение.



\## Порядок внесения изменений



1\. Создать ветку от актуальной `main`.

2\. Внести изменения и зафиксировать их коммитом.

3\. Отправить ветку в удалённый репозиторий: `git push -u origin имя-ветки`.

4\. Открыть Pull Request в ветку `main`, указав в описании,

&#x20;  что именно изменено и зачем.

5\. После слияния удалить ветку — и на GitHub, и локально.



\## Файлы



\- Кодировка всех текстовых файлов — UTF-8.

\- Служебные и временные файлы в репозиторий не попадают,

&#x20; для этого существует `.gitignore`.

\- Пароли, ключи и токены не добавляются в репозиторий ни при каких условиях.
